# 血と肉 Web — 記事の追加・編集のしかた

編集するのは `index.html` の **DATA SECTION**（`<script>` のすぐ下、`/* ===== DATA SECTION ===== */` から `/* ===== */` まで）だけです。

---

## 1. 記事（紙の報告書）を書く — `DOCS`

`DOCS` の中に、下の形で1件足します。`'名前'` は英数字の好きな名前（他と重ならないもの）。

```js
myDoc: { no:'記録 08', title:'タイトル', kind:'捜査記録',
  fields:()=>[
    ['項目','値'],
    ['通信','接続不能','1'],          // 3つ目に '1' を付けると赤字
  ],
  body:()=>[
    '本文の段落1。',
    '本文の段落2。{欠}けた文字は {} で囲む。',   // {x} の文字は欠落して見える
    {sec:'小見出し'},
    {spoiler:true, t:'ネタバレありのときだけ出る段落。'},
  ] },
```

- `kind` は紙の右上に出る種別（捜査記録／地域資料／報告書／異常存在 など自由）
- 人物資料にしたいときは `person:true` を付けると、写真欄付きの紙になる
- `ruby:'よみがな'` を付けると、タイトルの下によみが出る

## 2. 記事をどこに出すか決める

### A. 署の机に「捜査資料」として置く
`DESK_DOCS` に名前を足す。並び順もこの順。

```js
const DESK_DOCS = ['case','video','mountain','myDoc'];
```

### B. 署の机に「人物資料」として置く
`DOCS` に `person:true` 付きで書いたうえで、`PEOPLE` に1行足す（机の上のカードの内容）。

```js
{ id:'myDoc', name:'氏名', ruby:'しめい', age:40, line:'机の上で見える一行説明。', r:'1deg' },
```
`r` は紙の傾き。

### C. 山道の「気になる点……」として置く
`STEPS` の、出したい地点の `spots` に足す。

```js
spots:[ {doc:'meet',x:.40,y:.50}, {doc:'myDoc',x:.70,y:.62} ],
```
`x`・`y` は画面上の位置（0＝左/上、1＝右/下）。

見つけた報告書は自動で資料一覧に綴じられ、最後まで見ると全部読めるようになります。

## 3. 山道の地点を増やす — `STEPS`

`STEPS` に1行足すと、「進む」の回数が1回増えます。色の暗さ・赤さは段数に合わせて自動で割り振られます。

```js
{ place:'山道', text:['画面下に出る一文。','二文目。'],
  spots:[{doc:'myDoc',x:.5,y:.6}],
  figures:[{z:10,x:-2}] },
```

- `figures` … 血と肉の人影。`z` は奥行き（大きいほど遠く、霧に沈む）、`x` は道からの左右（マイナスで左）
- `comm:1` / `car:1` / `ret:1` … 通信・車両・帰路が途切れる
- `gone:2` … 人員が2人消える　`fall:1` … 神田が倒れる
- `village:1` … ここから村（木が減り家が出る）
- `infect:1` … ここへ進む前に「あなたは感染した……」
- `end:1` の地点は必ず最後に置く

## 4. 血と肉のSVGを入れる

1. SVGファイルを `img/` フォルダに入れる（例：`img/chitoniku.svg`）
2. DATA SECTION の `CHITONIKU_IMG` に場所を書く

```js
const CHITONIKU_IMG = 'img/chitoniku.svg';
```

山道の人影と、「血と肉」の報告書の図版の両方が、黒い仮の人影からこの絵に差し替わります。
空 `''` のままなら仮の黒い人影のまま。

## 5. 血と肉の種類 — `KINDS`

```js
{ name:'感染種', text:'説明' },
{ name:'純粋種', text:'説明', spoiler:true },   // ネタバレありのみ
```

---

### 動作確認のときの注意
進み具合はブラウザに保存されます。最初からやり直したいときは、二周目の資料一覧の一番下にある「記録を消して、最初の状態に戻す」を押すか、ブラウザのサイトデータを消してください。

## 6. 血と肉 No.01〜No.10 — `SPECIMENS`

上から順に No.01 … No.10。空欄のところを書き込むだけで記事になります。

```js
{ name:'名称', kind:'感染種', place:'御身神村', text:['説明の段落1。','段落2。'], img:'img/no01.svg' },   // No.01
```

- `name` … 名称欄とタイトルに出る（空なら「（未記入）」）
- `kind` … `'感染種'` か `'純粋種'`。純粋種はネタバレなしのとき「不明」と表示
- `place` … 確認地点
- `text` … 説明。空なら「（記述なし）」
- `img` … その個体のSVG。報告書の図版と、二周目の村に立つ人影に使われる。空なら `CHITONIKU_IMG`、それも空なら黒い仮の人影

一周目では「あなたは感染した……」のあと、資料一覧の「血と肉」の欄に並びます。二周目では、汚染された村の「気になる点」から開けます。
11件目以降を足すときは、`SPECIMENS` に1行増やせば No.11 として自動で増えます。

## 7. 入っている絵（img フォルダ）

| ファイル | 使われる場所 |
|---|---|
| `logo.svg` | 画面上部と、最初の閲覧方法の画面のロゴ |
| `chitoniku.svg` | 「血と肉」の報告書の図版（全員が並んだ絵） |
| `no01.svg`〜`no04.svg` | 血と肉 No.01〜No.04 の図版、山道・村に立つ人影 |

`no01`〜`no04` は、もらった血と肉達の絵を1体ずつ切り出したもの。左上から順に No.01（口が二つの個体）、No.02（爪の長い背の高い個体）、No.03（目が並んだ這う個体）、No.04（左下の個体）。
番号を入れ替えたいときは `SPECIMENS` の `img` を書き換える。山道に立たせる絵は `CREATURE_IMGS` で選ぶ。人影の大きさは絵の元の高さの比率で決まる（いちばん背の高い絵がおよそ人の背丈）。

## 8. 木・草むら・家のSVG

いただいた草木の素材を1本ずつ切り出して使っています。

| ファイル | 中身 |
|---|---|
| `tree1.svg` | 細めの木 |
| `tree2.svg` | 幹が何本もある木 |
| `tree3.svg` | 丸い樹冠の木（もとの絵の2本並びも含む） |
| `bush1.svg` `bush2.svg` | 草むら |

```js
const TREE_IMGS = ['img/tree1.svg','img/tree2.svg','img/tree3.svg'];
const BUSH_IMGS = ['img/bush1.svg','img/bush2.svg'];
const HOUSE_IMG = '';   // 家の絵ができたら 'img/house.svg'
```

- 明るい緑のままだと霧の中で浮くので、表示するときに暗く落とし、その場所の色（進むほど暗く、赤く）に寄せています。元のSVGは明るい緑のままです。
- 木・草むらを増やしたいときは、img に入れて配列に足すだけです。
- 家は空のうちは仮の図形で描かれます。絵の下端が地面に立つ位置になります。

## 9. 汚染と二周目（飯田が崖から落ちたあと）

- **一周目**：山の奥へ進むほど、資料一覧で読み返す紙（最初の事件概要も含む）に血が増えていく。森ではノイズが画面の端に残り、歩くたびに一瞬乱れる。御身神村の資料（`decay:true`）は、村の奥へ進むほど文字が欠ける。
- **二周目**：
  - 署の机は荒らされ、資料は血まみれで破れている。飯田以外の写真は黒塗り。
  - 「御身神山へ向かう」の先は、山道ではなく **血と肉に完全に汚染された村**。地名・状況表示・画面の文章・ボタンはすべて文字化けする。
  - 感染の演出、人が減る描写、崖の場面は出ない。プレイヤー自身が血と肉として村をさまよい、No.01〜No.10 の「気になる点」を見つける。最後まで進むと、また村の入口に戻る。
  - 「署へ戻る」は二度押しても暗転するだけで、三度目でようやく戻れる。
- 一周目の状態に戻すとき：二周目の資料一覧の一番下にある「記録を消して、最初の状態に戻す」。

## 10. ネタバレの有無で山道が変わる — `STEPS_ON` / `STEPS_OFF`

- **ネタバレあり**：`STEPS_ON`。これまでどおり、土砂 → 村 → 感染 → 飯田が崖から落ちる、まで進む。
- **ネタバレなし**：`STEPS_OFF`。土砂は起きず、帰路も通れる。村の手前で血と肉がちらっと見え、最後の地点で「進む」が「引き返す」になる（`back:1`）。押すと「飯田と神田は、引き返した。」で終わり、署へ戻る。
- どちらのルートでも `STEPS` の書き方は第3節と同じ。`back:1` の地点は必ず最後に置く。
- ネタバレ表示を切り替えると、**最初からやり直し**になる（進み具合・読んだ資料・山道の位置がすべて消える。進んでいる場合は確認が出る）。
- ネタバレなしルート用の資料は `traceOff` / `glimpseOff` / `backOff`（記録 03〜05）。ネタバレありのルートの資料とは番号が重ならないようにしてある。

## 11. 入口と「事件資料を閲覧する」（警察署のPC）

サイトを開くと、まず入口で2つから選びます。

| 入口 | 中身 |
|---|---|
| **事件を体験する** | これまでのゲーム部分そのまま（署の机 → 山道 → …）。進み具合も今まで通り保存される |
| **事件資料を閲覧する** | 警察署の端末という形の資料データベース。ゲームを進めていなくても全部の分類を見られる |

- ゲーム側の画面上部「入口へ」、資料側の「ログアウト」で入口に戻る。
- ゲームの進み具合と、資料側の閲覧区分は**別々に保存**される（資料を見てもゲームの進み具合は変わらない）。
- アドレスの `#play` がゲーム、`#db` が資料側。`#db.people.iida` のように個別ページへ直接リンクできる。

### 資料側の閲覧区分
- **一般**（ネタバレなし）／**機密**（ネタバレあり）。初めて開いたときに選び、右上の「閲覧区分」で切り替える。
- 一般では、`DB_LOCK` に入っている記録（今は 土砂・遭遇・村への道・神田・マザー）が「閲覧制限」になり、時系列でも黒塗りになる。
- それ以外の資料は、ゲームと同じく `{spoiler:true}` の段落と `on()` の分岐で、区分に合わせて中身が変わる。

### 分類と資料の割り当て — `DB_CATS`
資料データ（`DOCS` / `PEOPLE`）は**ゲームと共通**なので、記事を書き足せば両方に反映される。資料側でどの分類に出すかは `DB_CATS` の `docs` に名前を足すだけ。

```js
{id:'records', name:'捜査記録', ..., docs:['enter','comm','slide','trace','meet','way','kandaFall']},
```

| 分類 | 入っている資料 |
|---|---|
| 事件概要 | 事件概要 |
| 捜査記録 | 記録01〜07（ネタバレありルートの記録） |
| 関係者 | `PEOPLE` の全員（一覧 → 個別ページ） |
| 現場記録 | 御身神山・御身神村 |
| 時系列 | `STEPS_ON` から自動で作る（発端 → 山道の各地点 → 「飯田は崖から落ちた。」） |
| 資料・記録 | 配信映像の報告書・血と肉・マザー・個体記録 No.01〜 |

- ネタバレなしルート専用の記録（`traceOff` / `glimpseOff` / `backOff`）は、資料側には出していない。
- 関連資料のリンクは `DB_REL` で決める（`資料名:['関連1','関連2']`）。
- 資料側では `{x}` の欠け文字は「判読不能」の黒塗りで表示される。血の汚れ・破れ・二周目の演出は資料側には出ない（読みやすさ優先）。

## 12. 見た目の調整（2026-10 改修）

### 事件を体験する
- 画面上部に「御身神山事案」のタグと、いまの状況（署内 資料確認／現地捜索中 第n地点／記録終了）を表示。現地では赤い点が点滅する。
- 署の机の右側に **御身神山 略図**（経路と到達地点。行ったことのない地点は「？」）と **捜査メモ**（読んだ資料・関係者の確認・回収した報告書の数をチェック）を置いた。略図の下からも現地へ向かえる。
  - 略図の地点は `STEPS` の `place` から自動で作る。地点名を変えれば略図も変わる。
  - メモの項目は `memoHTML()` の `items` で変えられる。
- 山道では、現在地の下に「署 ●━●━◉┄○ 御身神村」の経路、右上に「捜索状況 第n地点」。
- 「気になる点……」は番号入りの黄色い証拠標識になった（番号は現地の報告書の順。二周目は個体番号）。
- 現地で開いた報告書には「現地回収」の印が押される。

### 事件資料を閲覧する
- 黒い端末風をやめ、署内の業務端末「捜査資料照会システム」に変更（明るい灰色の画面・紺のタイトルバー・罫線の表）。走査線や光る演出は無し。
- 入るときはログオン画面（利用者ID・パスワードは伏せ字、自動で認証）→ 初回のみ閲覧区分を選ぶ。
- ホームは「事件照会」：照会結果の表と「終結」の印、業務メニュー 1〜6。
- 資料は帳票の形：記録番号・種別・区分（一般／秘）、明朝の表題、罫線の表。欠け文字は黒塗り。
- 閲覧制限の記録は「閲覧権限がありません」の警告表示。
- 時系列は記録表（順・地点・記録内容・関連記録）。

## 13. 音の演出（2026-10 追加・同月 改修）

外部の音声ファイルは使わず、すべてWeb Audio APIでその場で合成している。画面右下に常に出ている丸い音声ボタンから、ミュートと音量を調整できる（`localStorage` に保存され、次に開いたときも覚えている）。

### 事件を体験する
- **署の机**：ごく小さい部屋の空気音のみ。二周目（資料が血まみれの状態）は不穏な低音と、かすかな鼓動が混ざる。
- **山道**（一周目）：風のノイズと低いドローン。奥へ進むほど音量が増す。
- **心臓の音**：署を出て山道に入ると、かすかに鳴り始める。**村に近づくほど大きく・速くなり**、鼓動のたびに風やノイズが一瞬沈むので、村の手前ではほかの音を押しのけるほど目立つ。
  - 山道の第1地点：ほとんど聞こえない（約54拍/分）→ 村の入口：約84拍/分・かなり大きい
  - 御身神村の中：約88〜102拍/分・最大級。奥へ進むほど速く、拍が少し乱れる
  - 感染後：重く、遅く落ちる（約58拍/分）。二周目の村は約66拍/分
  - 「進む」を押して歩いている間は、鼓動が一時的に速まる
  - 速さ・大きさは一拍ごとに少しずつ変わるので、急に切り替わらない
  - 村への近さは `approachOf()` で、`STEPS` の `village:1` の地点を「村の入口」として自動で計算する（ネタバレなしルートのように村に入らない場合は、最後の地点を入口扱い）
- 画面が一瞬乱れる演出に合わせて、ノイズのバーストや低い「ドン」という効果音が鳴る。
- 山道を「進む」たび・資料を開くたびに、足音や紙をめくる軽い音が鳴る。

### 事件資料を閲覧する（資料照会システム）
- **ログオン画面**：利用者IDとパスワードが一文字ずつ打ち込まれ、キーボードの音が鳴る → Enter → ディスクのアクセス音 → 認証できると「ピッ」。画面をクリックすると飛ばせる。
- **マウスのクリック**：画面のどこを押しても、押したとき・離したときにカチッと鳴る。ホイールを回すと小さなカリカリ音。
- **キーボード**：検索欄などでキーを打つと打鍵音。Enter・Spaceは少し重い音。
- **ページを移るたび**：短いディスクのアクセス音（ジジッ）。
- 端末のファンと電源のうなりが、ごく小さく鳴っている。
- 入口画面では音は鳴らない。

### 調整のしかた
`index.html` の `const Sound=(()=>{ ... })();` の中で調整する。
- 各シーンの音量・心臓音の速さと強さ：`setScene()` の中の `setHeart(速さ, 強さ, 環境音を沈める深さ)`
- 心臓音の音色：`thump()`
- キーボード・マウスの音色：`key()` `mouseDown()` `mouseUp()`
- ログオン時の打ち込みの速さ・利用者ID：`bootDB()` の `ID` と、`later(...)` の間隔

ブラウザの自動再生制限により、ページを開いた直後ではなく、どこか一回クリックやタップをした後から音が鳴り始める。
